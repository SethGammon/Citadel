## Primary beneficiary

The first beneficiary is an open-agent builder or small development team that
already uses a coding agent but cannot afford to treat the strongest model as
the default for every operation. Citadel is useful when the builder needs to
know whether a cheaper route still completed the repository operation after
tools, retries, verification, and recovery are counted.

## Distribution and adoption path

1. **Existing Claude Code or Codex user:** clone Citadel, run the runtime
   installer from the target repository, and begin with `/do`.
2. **Advanced local user:** add Ollama profiles and inspect signed operation
   receipts without enabling research mode for ordinary `/do` work.
3. **External stack builder:** implement the versioned adapter contract and run
   conformance. ROMA is the current external-stack example.
4. **Evaluator or researcher:** use the committed freeze, raw cells, dependency
   closure, sensitivity analysis, and offline verification without contacting
   the maintainer.

The funded onboarding measure is a reproducible clean-environment matrix across
Windows, macOS, and Linux with Claude Code and Codex paths, including setup
duration, generated paths, doctor output, rollback, and first governed route.
